# 麦麦优选智能体｜线上线下点餐规划助手

基于 MCP 协议开发的麦当劳 AI 智能体，专注**点餐方案规划**。支持单人点餐、多人拼单，自动搭配套餐并匹配优惠券，对比门店堂食与官方麦麦送外卖价格，附带门店筛选、限定商品库存查询，方案附带营养信息仅作展示。

> 本项目为比赛 Demo，**不实现真实下单与支付**。

## 核心功能

### 模块 1【核心主模块：多方案点餐搭配（单人 + 多人拼单）】

- 用户提交想吃餐品清单，选择就餐渠道：仅堂食 / 仅麦麦送 / 两渠道同时比价。
- 调用 MCP 查询菜单、套餐、渠道专属优惠券、门店库存。
- 逐个校验菜品，分两种弹窗提示：
  - 情况A（本店在售但当前门店无库存）：「XX为本店在售商品，但当前门店暂无库存，无法加入点餐方案。您可以移除该菜品，或更换门店查询」
  - 情况B（有货但仅支持单点）：「XX商品门店有货，无法搭配进套餐，计算价格时将按单品单点计价」
- 生成**方案1（首选方案）**：完整包含全部想吃的餐品，套餐+单点组合，自动匹配优惠券，计算总价。
  - 方案1 已是渠道最优 → 只输出方案1；
  - 价格偏高 → 额外生成**方案2（省钱备选）**，清晰标注被删减/替换的菜品；拼单场景标注菜品归属成员。
- 被动营养信息展示：整单总热量、钠含量，仅展示数据，不做饮食评判。
- 多人拼单：自动拆分账单，优惠金额分摊，输出每人应付金额。

### 模块 2【门店筛选模块（轻量化）】

- 输入位置与筛选条件（24小时营业、配备甜品站、有停车位），筛选附近门店。
- 查询选中门店限定款商品库存。
- 当前版本不实现排队预估（未来拓展）。

### 模块 3【线上线下比价模块｜堂食 VS 麦麦送】

- 仅对比门店堂食与麦当劳官方麦麦送（APP/小程序自带外卖），不接入美团、饿了么等第三方平台。
- 双渠道分别获取定价、专属优惠券、库存；麦麦送单独计算配送费与打包费并入总价。
- 输出对比明细：餐品原价、优惠抵扣、配送费、实付总价，并客观给出场景参考，不替用户做决定。
- 两渠道是独立优惠券体系，实时动态对比——外卖免配送/大额券活动时，麦麦送总价可能接近堂食。

### 附属彩蛋模块｜限定商品库存独立查询

- 单独功能入口，输入限定商品名称 + 目标门店，查询该限定款是否在售、有无库存。

## 技术说明

- 项目形态：WorkBuddy Skill（`SKILL.md`），智能体行为由 Skill 提示词驱动，所有数据能力来自麦当劳官方 **mcd-mcp** MCP Server。
- 未自定义/伪造任何 MCP 参数，全部使用官方工具与官方参数规则：
  - 堂食自取 `beType=1, orderType=1`（不传 beCode）；得来速 `beType=5`；麦麦送 `beType=2, orderType=2`（beCode 来自 delivery-query-stores）。
  - `calculate-price` 返回价格单位为**分**，展示时 ÷100 转为元。
  - ⚠️ 外送菜单商品 code 与堂食不同（外送为 99000029xx/90xxxx 系列，套餐 tag 含「外送价格」），比价时必须在外送菜单中重新映射 code，复用堂食 code 会报 60006「商品已售罄或不可售」。
- MCP 接入配置见 `mcp-config.example.json`（密钥使用环境变量占位符 `${MCP_TOKEN}`，严禁填写真实密钥）。
- 工具清单、每模块调用链与返回值处理详见 `MCP_INTEGRATION.md`。

## 边界与免责声明

本作品是基于 MCP 协议开发的比赛 Demo 项目，具备完整点餐规划能力。

- 智能体仅查询信息、生成点餐方案、计算价格与营养数据、筛选门店；**不提交订单，不处理支付，不接管用户账号**（不调用 create-order）。
- 所有价格、库存、优惠信息由 MCP 接口实时获取，仅供用户参考。
- 营养数据仅为信息展示，不构成饮食指导。
- 用户选定满意方案后，自行前往麦当劳官方 APP、小程序或线下门店完成点餐。

## 安装方法

1. 准备麦当劳官方 MCP Server 访问凭证，复制 `mcp-config.example.json` 为 `mcp-config.json`，将 `${MCP_TOKEN}` 替换为环境变量注入的真实凭证（或保持环境变量引用）。
2. 在 WorkBuddy（或其他支持 MCP 的智能体客户端）中加载本 MCP Server 配置。
3. 将 `SKILL.md` 作为 Skill 安装到智能体（WorkBuddy：技能 → 安装本地 Skill）。
4. 开始对话即可使用，触发词：点餐、拼单、麦当劳、麦麦送、比价、门店、库存、方案。

## 使用示例

```
用户：我在广州体育西路，想吃板烧鸡腿堡套餐加一份薯条，帮我搭配最省的方案
智能体：[query-nearby-stores 定位门店] → [query-meals 映射商品 code] →
        [query-store-coupons 匹配堂食券] → [calculate-price 计价]
        →【方案1（首选方案）】板烧鸡腿堡三件套 + 中薯条，实付 49 元，
          营养参考：总热量 XX kJ｜钠 XX mg

用户：我们三个人一起拼单，各自想吃的东西是……
智能体：生成方案后自动拆分账单、分摊优惠，输出每人应付金额

用户：堂食和麦麦送哪个划算？
智能体：双渠道分别实时查询计价（麦麦送含配送费+打包费），
        输出对比明细与客观场景参考

用户：查一下深圳华强北那家店有没有旋旋水手帽
智能体：[query-meals 匹配限定款] → 旋旋水手帽（521929）在售 ¥48.8，可加入点餐方案
```

## 目标用户

- 想吃麦当劳但纠结怎么搭配更划算的个人用户
- 多人一起点餐、需要拼单拆账的朋友/同事/家庭
- 不方便出门、需要对比堂食与外卖成本的用户
- 关注限定款商品上架动态的麦当劳粉丝
